# 产品愿景 · 医药向通用 Skill

## 问题

1. 生产大仓能力强，但对业务 **重、绑死历史金样、难自助沉淀**。
2. 业务真正想复用的参考，往往是 **自己认可的一份 PPT/视频**，不一定是仓库里的旧模板。
3. 领导期望：业务获得 **方法能力**（拆结构、定槽位、可再套），而不只是下载成品。

## 方向

把「复刻」从大仓里抽成 **独立、轻量、医药向** 的 Skill 集合：

| 要 | 不要 |
|----|------|
| 参考源由业务指定 | 强迫只用某套历史金样 |
| 结构级复刻 + 槽位表 | v1 就做完整渲染工厂 |
| 通用拆解流程 + 医药红线 | 行业无关的空壳办公助手 |
| 多 Skill 小而专 | 一个巨型 Skill / 巨型项目 |
| 产物可交给下游出片 | 本仓复刻生产库与设备安装 |

## 价值分层

| 层 | 能力 | 谁用 |
|----|------|------|
| L1 结构复刻 | 参考 → 方案卡 + 槽位表 | 业务 + WorkBuddy（本仓 v1） |
| L2 主题重填 | 同一结构换病种/单品 | 业务 |
| L3 协同出片 | 槽位表 → 其他 Skill / 生产仓 | 可选增强 |
| L4 组织入库 | 签样、settled、版本治理 | 生产仓 / 制作（不在本仓） |

## 成功标准（v1）

- 业务不装生产大仓，也能完成「拆参考 + 新主题填写清单」。
- 输出物足够清晰，制作或生产仓能据此继续，而不是从零理解对话记录。
- 新增第二种 Skill 时，不必改第一种 Skill 的核心流程。

## 非目标（本仓）

- 像素级自动复刻任意 PPT
- 克隆音色 / 数字人口型渲染
- 设备只读安装、业务设备密钥
- 替代药学/合规审定
